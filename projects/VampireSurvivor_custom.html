Addressable 리소스 관리

비동기 로드 / Remote 서버
Resource.Load 대신 Addressable로 라벨 기반 리소스 관리. Render 서버에 번들을 배포하여 빌드 없이 리소스 패치 가능. 비동기 로드 + 콜백으로 로딩 진행률 확인.

기존 Resource.Load 방식은 빌드 시 Resources 폴더의 모든 에셋을 포함하고, 경로 변경 시 코드에 문제가 생깁니다. Addressable은 경로를 자동 추적하고, 라벨 기반으로 필요한 리소스만 로드합니다. 나아가 Render 서버에 번들을 배포하여, 리소스 변경 시 클라이언트 재빌드 없이 서버의 파일만 교체하면 패치가 완료되는 구조를 구축했습니다.

오브젝트 풀링

IObjectPool / ResourceManager
IObjectPool(Unity 2021+) 기반 풀 구현. ResourceManager가 풀링 여부 판단 → PoolManager에서 Pop/Push. SpawningPool이 코루틴으로 _maxSpawnCount까지 자동 스폰.

게임 특성상 수많은 오브젝트를 생성/삭제하므로, 매번 new/destroy하면 메모리 단편화와 GC 부하가 심해집니다. ResourceManager가 중간 매개체로서 풀링 대상이면 PoolManager에서 Pop하고, 아니면 Instantiate합니다. SpawningPool은 코루틴으로 현재 오브젝트 수가 _maxSpawnCount보다 작으면 _spawnInterval 간격으로 자동 스폰합니다.

Grid + QuadTree 최적화

공간 분할 / Cell
맵을 Grid로 분할 → 각 칸에 Cell 부여 → 플레이어 min/max 범위의 Cell만 탐색. QuadTree로 아이템 줍기 등 추가 최적화 — 4분할 재귀로 범위 내 오브젝트만 처리.

다수의 오브젝트가 존재할 때 전체를 순회하면 비효율적입니다. 맵을 Grid로 분할하고 각 칸에 Cell을 부여하여, 플레이어의 탐색 범위(min/max)에 걸치는 Cell만 가져옵니다. 각 Cell이 포함한 오브젝트 목록을 반환하여 충돌/아이템 줍기 등을 효율적으로 처리합니다.

QuadTree

4분할 재귀 / 범위 탐색

QuadTree는 Grid와 별도로 아이템 등 산발적 오브젝트에 적용했습니다. 영역을 4분할 재귀로 쪼개고, 각 영역에 오브젝트가 일정 수 이상이면 다시 분할합니다. 특정 범위와 겹치는 오브젝트만 빠르게 추출하여 처리합니다.

무한맵

Camera Collider / 타일 재배치
카메라에 Collider/RigidBody 부착 → 타일과 OnTriggerExit 시 플레이어 이동 방향으로 타일 위치 재배치. 무한 스크롤 효과.

카메라에 Collider와 RigidBody를 부착하고, 타일에 MapTileController를 붙여서 카메라의 Collider와 OnTriggerExit 이벤트를 감지합니다. 타일이 카메라 영역을 벗어나면 플레이어의 마지막 이동 방향을 참조하여 해당 방향으로 타일을 재배치합니다.

스킬 시스템

SkillBook / 코루틴
SkillBook 컴포넌트가 스킬 목록을 List로 관리. 반복스킬/단발스킬 분류. 코루틴으로 스킬 실행 → 콜백으로 완료 통보 → 다음 스킬 준비. XML 데이터 기반 스킬 정의.

오브젝트는 Controller(이동 담당)와 SkillBook(스킬 담당) 컴포넌트를 가지며, 스킬은 반복스킬/단발스킬로 구분됩니다. 보스 몬스터의 경우 초기화 시 스킬을 등록하고, 스킬이 끝날 때마다 콜백 함수를 통해 다음 스킬 사용 준비를 합니다. 스킬 데이터는 XML로 정의하고 파싱하여 사용합니다.
