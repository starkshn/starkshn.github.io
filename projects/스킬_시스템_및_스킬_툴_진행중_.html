Stat(스탯, 능력치) 구현

❓구현이유

>

❓기능

Stat은 Stat, StatOverride, Stats로 구분이 되며

Stats는 Stat들을 관리하고 StatOverride는 Stat_HP, Stat_MP 이런식으로 각 Stat이 늘어나갈 때마다, Stat_Mage_HP, Stat_Mage_MP로 확장하는게 아니라 값을 덮어 쓰기 위한 용도로 만들었습니다.

>

State FSM(상태에 대한 유한 상태 기계 구현)

🧑‍💻결과물

이동과 구르기, Stat_HP 조절로 죽음과 부활을 FSM으로 구현한 결과물입니다.

>

❓구현이유

어떤 상태를 추상화된 개념을 관리할 때 if, switch문을 통해서 관리하는 것이 아니라 구체적인 객체로 나타내어 유연성과 확장성을 가질 수 있게 하기 위해 State라는 것을 FSM으로 구현하였습니다.

>

🧑‍💻설명

State(상태)끼리는 전이(Transition)이 발생할 수 있고 상태끼리 전이가 발생하는 과정을 StateMachine이 관리할 수 있도록 하였습니다.

>

✏️결과

각 상태에 따라 if → update → 전이 → 뛰는 상태 if → update → 전이 이런식의 if문이 들어가는 코드가 아닌 각 상태는 각자의 역할만 수행할 수 있도록 구조가 잡히게 되었고 유연성이 확보되었습니다.

>

📜클래스 구조 도식화

클래스간 포함관계를 도식화 하였습니다.

Entity라는 객체(Player, Monster 등)가 MonoStateMachine을 가지고 있고, MonoStateMachine이 StateMachine의 Update를 호출하여 상태를 제어합니다.

>

  • Entity : MonoStateMachine을 담고 있는 본체 클래스 입니다.
  • MonoStateMachine : StateMachine을 제어하는 객체입니다.
  • StateMachine : State, StateTransition을 제어하는 객체입니다.
  • StateTransition : 전이(변화)를 담당하는 객체입니다.
  • StateData : 상태라는 것이 가질 수 있는 데이터를 나타내는 객체입니다.
  • State : 상태를 나타내는 객체입니다.

📜State 구조 도식화

상태를 FSM으로 구현하기 위해 제작된 클래스들입니다.

>

✏️Code

상태라는 추상화된 개념을 객체화한 클래스입니다.

추상클래스로 제작하였으며, 해당 클래스를 상속받아 State_Idle과 같은 작업을 할 수 있도록 하였습니다.

>

전이(Transition)이라는 추상화된 개념을 객체화하였습니다.

각 상태는 전이라는 개념을 가지고 어던 조건에서 어떤 상태로 넘어갈 수 있는지를 나타내는 클래스입니다.

>

StateMachine.cs : 스테이트 머신의 코드들입니다.

실제 상태를 전환(ChangeState)하고 상태가 변경(전이)될 수 있는지(TryTransition)를 구현한 코드입니다.

>

TargetSearch 구현

❓구현이유

단순이 충돌체를 통해 찾는 방법, B라는 방법을 통해 찾는방법으로 코드를 들려나가는 것이 아닌 찾는 방법을 두가지로 쪼개에 기준점을 잡는 클래스, 기준점을 바탕으로 실객체를 찾는 클래스로 나누어 모듈화를 통해 보다 확장성 있게 타겟을 찾는 방법을 만들기 위하여 구현하였습니다.

>

✏️기능설명

타겟을 찾기전 기준점을 잡아주는 TargetSelectionAction, 찾은 기준점을 바탕으로 실제 타겟들을 찾는 TargetSearchAction두 큰 클래스로 나누어 모듈화를 할 수 있도록 하였습니다.

필요한 기능들을 해당 두 클래스를 상속받아 각자의 기능을 구현할 수 있도록 하였습니다.

>

🧑‍💻결과

색이 칠해진 범위 안에 타겟들이 있는지를 마우스 클릭으로 찾을 수 있는 타겟 검색 방법

>

특정 범위안에 있는 타겟들을 검색할 수 있는 방법

>

부채꼴 범위안에 있는 타겟들만 검색할 수 있는 방법

>
